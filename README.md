# MassBank-similarity-api

A REST interface wrapping [matchms](https://github.com/matchms/matchms) for
MassBank.

This server was generated by the [OpenAPI
Generator](https://openapi-generator.tech) project and uses the
[Connexion](https://github.com/zalando/connexion) library on top of Flask.

The service prepares reference peaks once as read-only arrays shared by request
threads. The comparison loop is compiled by Numba and releases the GIL, allowing
threads to calculate similarities in parallel while sharing one reference
dataset. The API contract, generated models and controller routing use the
`python-flask` generator.

## Requirements

Python 3.13, [uv](https://docs.astral.sh/uv/getting-started/installation/), Java
and Maven (for OpenAPI code generation).

## Configuration

This microservice is configured with environment variables. The reference
spectra are initialized from a local file directory (root directory). The
directory location needs to be configured in the environment variable
`DATA_DIR`. For MassBank we configure the service with the latest MassBank-data
release in file format.

```bash
# Download the latest MassBank-data release into MassBank-data.
version=$(
  curl -s \
    https://api.github.com/repos/MassBank/MassBank-data/releases/latest |
    grep "tag_name" | sed "s/\"tag_name\": //g" |
    sed "s/\"//g" | sed "s/,//g" | sed "s/ //g"
)
mkdir -p MassBank-data
archive_base="https://github.com/MassBank/MassBank-data/archive/refs/tags"
wget -qO- "$archive_base/$version.tar.gz" |
  tar -xzf - -C ./MassBank-data --strip-components=1
```

Now we set the environment variable:

```bash
export DATA_DIR="./MassBank-data"
```

A more verbose logging can be activated by setting environment variable VERBOSE
to "true".

```bash
export VERBOSE=true
```

The application context path can be configured with the environment variable
CONTEXT_PATH. If not set / is used by default.

The server uses two regular Waitress workers by default. Set `THREADS` to
change that number, for example:

```bash
export THREADS=4
```

The service loads reference data once at startup and logs the dataset version
from `DATA_DIR/VERSION` when present. Startup temporarily requires memory for
both the Spectrum objects and the packed arrays. A load failure prevents the
service from starting. Changes on disk are not picked up at runtime.

For Kubernetes HTTP probes, use `/readiness` and `/liveness` on the normal
API port (`8080`). Prefix both paths with `CONTEXT_PATH` if configured.
The same Waitress server reserves a separate worker and queue for probes.
Readiness requires a fully loaded snapshot. The port does not accept
connections during loading, so allow enough startup time with a `startupProbe`.
Once the server is listening, liveness does not check the reference data.

## Usage

To run the server, sync the dependencies, generate the server code and start the
server like this:

```bash
uv sync --locked
mkdir -p gen && bash generate.sh
uv run --locked python -m similarity_api_impl
```

You can find the swagger ui at http://localhost:8080/ui/ and the OpenAPI
definition at http://localhost:8080/openapi.json in your browser.

Run tests with `uv run python -m unittest discover -s test`. The API tests use
the service app with `DATA_DIR` set to `test/MassBank-test-data`. After changing
dependencies in `pyproject.toml`, run `uv lock` and commit the updated
`uv.lock`.

## Running with Docker

The Docker image uses the same launcher as `python -m similarity_api_impl`.
Set `THREADS` in the container environment to change the regular worker count.

To run the server in a Docker container, execute the following commands:

```bash
# Download the latest MassBank-data release into MassBank-data.
version=$(
  curl -s \
    https://api.github.com/repos/MassBank/MassBank-data/releases/latest |
    grep "tag_name" | sed "s/\"tag_name\": //g" |
    sed "s/\"//g" | sed "s/,//g" | sed "s/ //g"
) &&
archive_base="https://github.com/MassBank/MassBank-data/archive/refs/tags" &&
wget -O "MassBank-data-$version.tar.gz" \
  "$archive_base/$version.tar.gz" && \
tar -xzf MassBank-data-$version.tar.gz && \
mv MassBank-data-$version MassBank-data

# building the image
docker build -t massbank-similarity-api .

# starting up a container with directory to MassBank data (reference)
docker run -p 8080:8080 \
-v $(pwd)/MassBank-data:/MassBank-data \
-e DATA_DIR='/MassBank-data' \
massbank-similarity-api
```

Prebuild docker images are available from
[quay.io/massbank/massbank-similarity-api][images]. The fastest way to get
things running is:

```bash
# get the latest reference data (as described above)
# ...

# starting up a container
docker run -p 8080:8080 \
-v $(pwd)/MassBank-data:/MassBank-data \
-e DATA_DIR='/MassBank-data' \
quay.io/massbank/massbank-similarity-api:latest
```
